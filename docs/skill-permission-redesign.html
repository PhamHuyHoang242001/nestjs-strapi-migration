Phân quyền Skill (định hướng — 3 code)

Shipped: 4 workspace × 2 code + SO pending-only + supporter — see skill-permission-redesign.md. This HTML is the unused 3-code sketch.

Tách skill_upload thành 3 code: skill_create, skill_edit, skill_approve. Không có skill_view / skill_delete.

Edit skill = tạo version mới (PUT /items/:id/versions). Approver không sửa pending. Người nghỉ: chuyển owner, không đẩy SO sửa nội dung.

  A --> Rev[Hang cho duyet, approve/reject, an/hien package]
Role Code Được làm
Skill Viewer không Đọc skill active
Skill Uploader skill_create và skill_edit Tạo skill; edit skill (tạo version mới) trên package mình tạo; sửa version rejected newest (mình submit hoặc mình tạo package)
Skill Approver skill_approve (không create, không edit) Hàng chờ, approve/reject, ẩn/hiện, xem inactive. Không sửa pending, không bump skill người khác

Nếu không gắn guard skill_create trên POST: mọi login đều tạo được; Uploader chỉ cần skill_edit. Hai code còn lại giữ nguyên.

Việc API Guard Service còn chặn
Tạo skill POST /items skill_create —
Edit skill = tạo version mới PUT /items/:id/versions skill_edit Người tạo package. 409 nếu đang có pending
Sửa version rejected PUT /versions/:vid skill_edit Newest rejected; submitter hoặc người tạo package
Sửa version pending PUT /versions/:vid — Không cho. Approver reject; author (hoặc owner mới) sửa lại
Approve / reject POST .../approve, .../reject skill_approve Chỉ version pending
Ẩn/hiện package PATCH /items/:id/status skill_approve active / inactive
Chuyển owner PATCH /items/:id/owner author / manager / SO Đổi created_by. Không sửa nội dung skill
