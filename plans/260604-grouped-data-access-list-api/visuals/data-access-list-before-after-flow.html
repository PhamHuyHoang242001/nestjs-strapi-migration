GET /v1/data-access/list

So sanh flow lay data truoc va sau khi refactor tu flat rows sang grouped response

1 — Overview

Van de: Endpoint /list cu tra ve flat rows (1 row = 1 subject). Rule co N roles + M users tao ra N+M rows. Pagination ap dung tren flat rows, khong the hien duoc "bao nhieu record duoc cap quyen".

Giai phap: Group by (data_id, module_id). Moi group = 1 record voi mang rules cua no. Pagination o cap group. Bo sung record_name tu target table.

2 — Flow cu (Before)
Query Strategy

Dung 1 CTE lon (flattened) chua 2 branch UNION ALL: role branch va user branch. Ket qua la flat rows, moi row = 1 subject voi 1 rule. Pagination ap dung truc tiep tren flat result.

Flow xu ly cua list() method cu:

CTE Flattened Structure
WITH flattened AS (
  -- Role branch: 1 row per (rule, role)
  SELECT da.id as rule_id, da.data_id, ...,
         'role' as subject_type, r.id as subject_id,
         r.name as subject_name, NULL::jsonb as permissions
  FROM data_access da
  JOIN data_access_roles dar ON dar.data_access_id = da.id
  JOIN role r ON r.id = dar.role_id

  UNION ALL

  -- User branch: 1 row per (rule, user) voi permissions aggregated
  SELECT da.id as rule_id, da.data_id, ...,
         'user' as subject_type, u.id as subject_id,
         u.full_name as subject_name,
         json_agg(json_build_object('id', p.id, 'name', p.name))
  FROM data_access da
  JOIN data_access_users dau ON ...
  JOIN users u ON ...
  JOIN permission p ON ...
  GROUP BY ..., u.id
)

Rule co 3 roles + 2 users → 5 flat rows. Pagination count = tong flat rows (khong phai tong records).

3 — Flow moi (After)
Query Strategy

Dung 4 buoc tuan tu: (1) Count + paginate groups, (2) Fetch rules cho groups do, (3) Batch lay record names, (4) Assemble response. Pagination o cap group, khong o cap flat row.

Flow xu ly cua list() method moi:

    B --> Q1["Step 1a: COUNT distinct groups
SELECT COUNT(DISTINCT data_id, module_id)
FROM data_access da ..."]
    Q1 --> Q2["Step 1b: Paginated groups
SELECT data_id, module_id, table_name,
module_path, module_name,
MAX(created_at) as latest_created_at

1
Count + Paginate Groups

Query SELECT DISTINCT data_id, module_id voi cac filter (module_id, scope_type, role_id, user_id, search + record_name). Pagination ap dung o day — LIMIT/OFFSET tren groups, khong tren flat rows.

2
Fetch Rules cho Groups

Reuse CTE flattened (UNION role + user), nhung them dieu kien WHERE (data_id, module_id) IN (...) chi lay rules cua groups trong trang hien tai. Khong fetch toan bo.

3
Batch Record Names

Group cac data_id theo table_name, query moi target table 1 lan. VD: SELECT id, "name" FROM bi_hub_reports WHERE id = ANY($1). Khong N+1.

4
Assemble Response

Map rules vao tung group theo key data_id-module_id. Attach record_name tu batch lookup. Fallback "ID: {data_id}" neu record da bi xoa.

Diem manh cua approach moi
  • UX tot hon: FE hien thi danh sach records, moi record expand ra xem rules
  • Pagination chinh xac: "Trang 1 co 10 records" thay vi "10 rows co the la 3 records"
  • Thong tin record: Hien thi ten report/document ngay trong list, khong can click vao details
  • Tim kiem manh hon: Tim theo ten record ngoai data_id va ten user/role
  • Khong N+1: Batch fetch record names theo table_name, moi table query 1 lan
