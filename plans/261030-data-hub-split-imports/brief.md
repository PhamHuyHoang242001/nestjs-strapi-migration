## Order and endpoints (each: GET template?example=true|false → .xlsx; POST ?dry_run=true|false multipart `file` ≤5MB, default dry_run=true; same response shape as today: {dry_run, summary, <entities>[{sheet,row,ref?,status,id?,code?}], issues[{sheet,row,column?,code,message,warning?}], result_file{file_name,content_base64}} with "Kết quả"/"Chi tiết" columns appended)
1. **App thụ hưởng** — `/v1/data-hub/consumer-imports` (permission dh_consumer_create). Sheets in order: `HUONG_DAN`, `APP_THU_HUONG`, `DANH_MUC`.
   APP_THU_HUONG columns: Mã app* (^[A-Z0-9_]{2,100}$ uppercased), Tên app*, Phân loại* (INTERNAL_APP|PARTNER_ECOSYSTEM dropdown), Mã khối chủ quản* (division code), Mô tả ngắn* (≤200), SO APP* (emails `;`, 1..20, live users). Validate with CreateConsumerDto; create via the consumer write service (own transaction per row). Duplicate code in DB/file → error. DANH_MUC: divisions (code,name), categories.
2. **Thuật ngữ chuẩn hoá** — `/v1/data-hub/logical-term-imports` (dh_logical_term_create). Sheets: `HUONG_DAN`, `THUAT_NGU_CHUAN_HOA`.
   Columns: Mã thuật ngữ* (≤255, unique case-insensitive vs DB + file), Mô tả ngắn* (≤400), Ví dụ (≤1000). Creates logical terms WITH NO physical terms (user decision: allowed only for import; the UI POST/PUT /logical-terms keep requiring ≥1 physical). History CREATE snapshot with physical_terms: [].
3. **Dịch vụ dữ liệu** — keep `/v1/data-hub/data-service-imports` (dh_data_service_create + department membership as today). Sheets: `HUONG_DAN`, `DICH_VU_API`, `DICH_VU_SFTP`, `BANG_NGUON_PHYSICAL_TERM`, `DANH_MUC`.
   Changes vs today: REMOVE the consumer (App thụ hưởng) column from both service sheets (services are created with 0 consumers — allowed only for import; the UI POST/PUT /data-services still require 1..20); REMOVE the logical-term column from BANG_NGUON_PHYSICAL_TERM and the whole `LOGICAL_TERM_MOI` sheet (mapping moves to import 4). Source tables + physical terms stay here (user decision). Everything else (service code rule, users by email, org codes, spec fields, Text format, dropdowns, file guard, per-cell issues) unchanged.
4. **Quan hệ** — `/v1/data-hub/relation-imports` (needs dh_data_service_update for sheet 1 rows + department membership of the service; dh_logical_term_update for sheet 2 rows). Sheets: `HUONG_DAN`, `DICH_VU_APP_THU_HUONG`, `THUAT_NGU_NGHIEP_VU_CHUAN_HOA`, `DANH_MUC` (optional).
   - DICH_VU_APP_THU_HUONG: Mã dịch vụ* (existing live service_code), Mã app thụ hưởng* (existing ACTIVE consumer codes, `;`). Per service: ADD these consumers to the service's current consumers (merge, never remove) → write a NEW VERSION through the normal update path (same diff/history/permission logic as PUT /data-services/:id, changelog_note "Import quan hệ app thụ hưởng"); resulting total must be ≤20; nothing new → warning ALREADY_LINKED, no version.
   - THUAT_NGU_NGHIEP_VU_CHUAN_HOA: Mã dịch vụ*, Tên bảng nguồn*, Mã thuật ngữ nghiệp vụ* (identify a live physical term of that service in that table, case-insensitive), Mã thuật ngữ chuẩn hoá* (existing live logical). Per logical term: set = current physicals ∪ new ones, through the logical write update path (version+1, history; PHYSICAL_ALREADY_MAPPED if the physical is mapped to ANOTHER logical → row error; already mapped to the same → warning).
   - Each service / each logical term is applied in its own transaction; a group is applied only if all its rows are valid.
